# Xiaomi NFC Photo Bridge · 小米一碰传图

面向 **非小米 Windows 台式机 / 组装机 + 小米手机** 的实验性一碰传图工具：给普通台式机配一张 NFC 贴纸，手机碰贴纸后，自动通过小米系统分享发送选中的图片或当前屏幕截图。

## 这个项目给谁用？

**主要服务于没有小米笔记本原生一碰互联体验的非小米台式机用户。** 前提是已安装适用的“小米互联服务 Windows 版”，并能手动接收小米手机发来的图片；本项目补充 NFC 触发、自动分享、发送后返回和临时截图清理。

**小米 / REDMI 笔记本不是本项目的目标用户。** 已具备官方互联及一碰传功能的机型，直接使用原生功能即可，无需为了传图安装本项目；具体原生功能以机型支持情况为准。

其他品牌笔记本属于额外适配场景，当前不作为本教程的主要配置对象。台式机上显示的“我的笔记本”只是实测时系统分享面板的设备名称，**不表示必须使用笔记本**；适配时应匹配自己的电脑名称。

**项目处于原型阶段。2026-10-19 已完成真实 NFC 贴纸触发及连续“选图发送 → 截屏发送”测试，用户反馈断开调试连接后正常。不是小米官方软件，也不代表所有设备都已适配。**

## 换一台电脑或手机怎么用？

请阅读 **[不同设备适配与 Agent 操作指南](docs/ADAPTATION.md)**，包含：

- NFC、无障碍和系统传输各自负责什么。
- 小米 / 其他 Android / iPhone，以及不同电脑的适配边界。
- 从手动传图到自动传图、截图、返回和 NFC 的完整验收步骤。
- 需要修改的代码位置、常见故障和可直接复制给 Agent 的诊断与适配指令。

**当前不是安装后自动适配所有设备的软件。** Agent 可以采集型号、版本和界面控件，再协助修改源码；系统授权、手机确认和实体碰 NFC 测试仍需要使用者完成。

## 功能

- 在小米相册勾选一张或多张图片：自动点击分享，再点击原生设备“我的笔记本”。
- 没有勾选图片：截取当前屏幕，通过系统分享发送。
- 检测到目标设备显示“已完成”后，关闭分享面板，返回之前的页面。
- 截图传输成功后，只删除本次生成的手机私有临时截图；保留电脑文件和相册原图。
- 内置可写 NFC 标签的 NDEF 写入界面。

## 使用前准备

1. 先按 **[非小米台式机与小米手机配置教程](docs/SETUP.md)** 安装官方“小米互联服务 Windows 版”，打开手机互联开关，完成设备发现和手动收图测试。教程提供下载入口、设置路径、验收方法和故障排查；此阶段不需要 NFC 贴纸或 USB 调试。
2. 编译并安装本应用。当前代码固定匹配系统设备名称 **我的笔记本**；不同名称需修改 `NativeTarget.java` 并重新编译。不要同时使用多个同名设备。
3. 在 Android 无障碍设置中启用“碰传桥接测试”；升级后关闭再开启，刷新权限。
4. 在小米系统“其他权限”中允许 **后台弹出界面**，否则截图分支可能无法显示分享面板。
5. 初次测试请使用不含敏感内容的页面和图片。

## 使用哪种 NFC 贴纸？怎么写入？

本次选购规格为 **NTAG213 白标，直径 25 mm**，用于贴在显示器塑料边框。购买时确认以下规格：

| 项目 | 规格 |
| --- | --- |
| 芯片型号 | **NTAG213** |
| 外形 | 圆形，直径 **25 mm**，白色覆面、带背胶 |
| 数据格式 | 支持 **NDEF**，空白、未锁定、可重复写入 |
| 安装位置 | 显示器塑料边框；若紧靠金属或贴金属机箱，选抗金属款并先测试 |

淘宝等平台可搜索：`NTAG213 白标 25mm NFC 可擦写`。湿标通常能看见天线，白标多一层白色面材；相同芯片下主要是封装外观不同。“进口芯片”属于商家描述，本项目不作原厂真伪认证。NTAG215/216 是可评估的替代规格，本项目未逐型号实测。

1. 安装当前版本，打开手机 NFC，保持解锁；确认本应用无障碍服务已启用。
2. 打开“碰传桥接测试”→“写入桥接 NFC 贴纸”→“开始写入”。
3. 贴纸靠近手机背部 NFC 区域，保持不动，直到显示写入成功。
4. **退出写入页面**，回相册勾选图片，或停在允许截图的页面。
5. 碰一次贴纸，振动后移开，等待发送；电脑需保持互联服务运行。

**写入会覆盖贴纸现有 NDEF 内容。** v11 起写入两条记录：第一条是 URI：

```text
xiaomi-photo-bridge://send/desk-1
```

第二条是 Android Application Record（AAR），包名 `local.codex.xiaominfcprobe`。本次实测系统会拒绝单独的自定义 URI；增加 AAR 后才成功启动应用。因此旧版写过贴纸的用户，需要用新版重新写一次；v11 升到 v12 不必再写。更改应用包名时，写入的 AAR 也必须匹配实际包名。

贴纸只触发应用，图片实际由小米互联传输，不会写进贴纸。相册原图不会被删除；只有确认发送成功的本次临时截图才会自动清理。未确认完成时保留截图，离开旧分享窗口后释放观察状态，允许下次碰触，不会取消系统正在进行的传输。

## 从源码构建（Windows）

需要 Python 3、JDK 17、Android SDK Platform 35 和包含 aapt2、zipalign、d8.jar、apksigner.jar 的 Android Build Tools。

构建脚本使用如下目录布局，可通过 `ANDROID_BRIDGE_TOOLCHAIN` 环境变量指定目录：

```text
toolchain/
  jdk/.../bin/javac.exe
  platform/.../android.jar
  build-tools/.../aapt2.exe
  build-tools/.../zipalign.exe
  build-tools/.../lib/d8.jar
  build-tools/.../lib/apksigner.jar
```

```powershell
python .\build_probe.py
```

脚本会运行六组 Java 测试、编译、生成本地调试签名，并验证 APK 签名。输出为 `build/XiaomiNfcBridge-probe-v12.apk`。首次构建会生成自己的调试密钥；**无法覆盖安装使用其他密钥签名的 APK**。工具链、APK、密钥均不提交到源码仓库。

包名：`local.codex.xiaominfcprobe`。这是调试原型，manifest 保留 `debuggable=true`。

## 诊断入口

启用无障碍后，在手机准备好页面，再从已授权的 ADB 执行：

```powershell
adb shell am broadcast --user 0 -a local.codex.xiaominfcprobe.TEST -n local.codex.xiaominfcprobe/.BackgroundNfcProbeReceiver -f 0x11000020 --es mode bridge
adb logcat -s XiaomiNfcBridge:I
```

诊断广播受 Android `DUMP` 权限保护。不要在传输时同时运行 `uiautomator dump/events`，它可能打断无障碍服务。

## 隐私与限制

- 无障碍服务能够读取界面，截图权限能够捕获屏幕；请理解权限后再启用。未主动触发时不截屏、不自动点击。
- 相册原图由系统分享发送；截图先保存到应用私有目录。成功确认后清理本次截图，失败或超时保留临时文件；卸载应用可清理其私有数据。
- 只截当前屏幕，不提供长截图。系统禁止截图的页面会失败。
- 完成判断依赖小米原生设备行、状态文字和无障碍节点，系统升级可能导致失效。未识别完成时不自动删图。
- `ProbeActivity` 的“旧版诊断”按钮及相关 MiShare/旧 NFC 代码仅保留研究用途，个人设备标识已替换为占位值；日常无障碍分享流程不依赖它们。不要使用该按钮验证日常流程。
- 不包含手机相册内容、调试日志、小米系统 APK、系统框架、第三方工具链、原作者签名密钥或账号凭据。
